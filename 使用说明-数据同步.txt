TaskTable 0.1.8-local —— 数据可同步版（本地补丁）
==================================================

这个文件夹 = 原版 0.1.5 + 若干本地改动。核心一条：任务数据不再锁在浏览器的
IndexedDB 里，而是存成一个 JSON 文件，放在【用户目录】，可被绿联云 / 任何网盘同步，
同时程序目录保持干净（可以直接传到 GitHub）。


===========================================================
一、数据在哪
===========================================================
  默认（每台电脑各自一份）：

      %APPDATA%\TaskTableData\data\state.json
      C:\Users\16542\AppData\Roaming\TaskTableData\data\   ← 就是这个文件夹

  同目录下还会有：
      .stignore                     让同步工具忽略冲突备份
      state.conflict-<机器名>-<时间>.json   两台机器都改过时的留档

  程序里看路径：设置 → 数据 → 「数据文件」那一行，右边有「打开文件夹」。

  想换位置（比如直接指到你已有同步夹里），两种方式：
    1) 在 %APPDATA%\TaskTableData\data-path.txt 里写一行完整路径
       （注意是 TaskTableData 这一层，不是 data 里面）
    2) 启动时设环境变量 TASKTABLE_DATA_FILE=<完整路径>

  优先级：环境变量 > %APPDATA%\TaskTableData\data-path.txt
          > 程序目录\data-path.txt（旧版遗留，兼容）> 默认位置

  ⚠️ data-path.txt 是【本机配置】，不要放进同步文件夹里 ——
     否则 A 机写的路径会被同步到 B 机，把 B 机的数据指到不认识的位置。
     所以同步任务只圈 data 这一个小文件夹。


===========================================================
二、旧数据自动迁移（只发生一次）
===========================================================
  0.1.6 早期版本把数据放在 <程序目录>\data\state.json。
  新版第一次启动时：
    1) 把那份 state.json 复制到 %APPDATA%\TaskTableData\data\state.json
    2) 把旧的 <程序目录>\data 整个改名成 data.migrated-<时间戳>（留档，不删）
  之后程序目录里就没有任何个人数据了，可以放心打包上传。

  如果新位置已经有 state.json（真的已经有数据），迁移不会覆盖它。


===========================================================
三、绿联云同步怎么配
===========================================================
  同步引擎是 Syncthing 内核，一个"文件夹对"就是 本地某文件夹 ↔ NAS 某文件夹。

  做法 A（推荐）：
      本地： C:\Users\16542\AppData\Roaming\TaskTableData\data
      NAS ： 随便一个空文件夹，例如 /我的文件/TaskTable
      方向： 双向
      第二台电脑：把【它自己的】...\TaskTableData\data
                  和 NAS 上【同一个】文件夹做双向同步。

  做法 B（不想新建同步任务）：用 data-path.txt 指到已有同步夹里
      1) 在比如 D:\Desktop\建模-NAS 里建子文件夹 TaskTable
      2) 写 %APPDATA%\TaskTableData\data-path.txt，内容一行：
           D:\Desktop\建模-NAS\TaskTable\state.json
      第二台电脑照抄，写它自己的本地路径。

  注意：
    · 必须是「双向」，设成仅上传/仅下载那台就只能看不能改。
    · 写文件用「临时文件 state.json.tmp + 改名」原子替换，半成品不会被同步出去
      （Syncthing 默认忽略 *.tmp）。
    · 同步工具自己打架时可能留下 state.sync-conflict-*.json，程序不读它，可删。


===========================================================
四、程序行为 / 限制
===========================================================
  · 启动时读一次数据文件；平时靠导航栏的「↻ 同步」按需重读。
  · 两边都改过：先把对方那版留成 state.conflict-*.json，再按任务 id 合并
    （两边新增的都保留，同一条以 lastTouchedAt 更新的一方为准）。
    这是「并集」策略 —— 删除不会跨机器传播，另一台还留着旧任务时会被合并回来。
  · 数据文件万一丢了（误删 / 同步抽风）：启动时会自动从旧版浏览器数据库恢复一份，
    不会显示空列表；只有你在设置里点过「清空所有数据」之后才不恢复。
  · 单实例运行：同一个 profile 只能开一个窗口，重复启动只会把已有窗口提到前面。


===========================================================
五、界面上动了哪些地方
===========================================================
  1) 导航栏新增两个按钮（原作者 0.1.6 已把「已完成/提醒」合并成「历史」）：
       ↻ 同步      重新读一次数据文件再合并（另一台改过、绿联云同步完就点它）
       （中央的「速录」圆钮保留原作者的方案，本地版不再另加「+ 记一件」）
  2) 「今天」列的任务卡：标题独占一行，倒计时徽章另起一行，不再把标题挤成两列。
  3) 「今天」列的卡片底部多一行进展记录：
       折叠：▸ 进展 3  最新一条的预览…
       展开：▾ 进展 3  全部记录（新→旧，带时间）
     默认折叠，不写进数据文件。四象限里的紧凑卡片不加。
  4) 顺手修了 ≤960px 单列布局下「今天」列内容被四象限卡片盖住的老问题。


===========================================================
六、传到 GitHub 之前要注意
===========================================================
  · 仓库根目录已经放好 .gitignore，忽略：data/、data.migrated-*/、data-path.txt、
    *.conflict-*.json、state*.json —— 即使你把 data-path.txt 指回程序目录也不会误传。
  · TaskTable.exe 有 246MB，超过 GitHub 单文件 100MB 硬限制，直接 git add 会失败；
    想让人「下载就能用」，请用 Releases 上传压缩包（单文件上限 2GB）。
  · resources/app/node_modules 已在 .gitignore 里（renderer 早把 react 打进 dist 的
    bundle，运行时不需要它）；忽略只是让仓库小一点，本地文件不动、程序照跑。
  · 只想公开源码的话，上传 resources/app 这一层（main.cjs / preload.cjs / dist）就够。


===========================================================
七、想退回原版
===========================================================
  resources\ 下留着 app.asar.orig-0.1.5.bak：
  把 resources\app 目录删掉（或改名），再把该文件改名回 app.asar 即恢复原版。
